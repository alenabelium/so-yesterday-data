## TL;DR

Massive models like Claude Fable 5 shift the bottleneck from model capability to human 'task imagination.' Users must stop writing small, safe prompts and start delegating large, ambiguous projects. This requires preparing data packs and defining success criteria, transforming the user from a prompt engineer into a model manager who oversees high-stakes execution.

## The argument

### The Constraint Shift
- **Anchor Timestamps**: ['00:01:20']
- **Claim**: With 10-trillion parameter models, the limit is no longer model ability but the user's capacity to imagine large tasks. The new constraint is our ability to define the ask, not the model's capacity to execute it.
- **Role**: definition

### Delegation vs. Task Imagination
- **Anchor Timestamps**: ['00:07:10']
- **Claim**: Unlike standard delegation of known tasks, task imagination targets ambiguous, 'dirty' work that isn't on any tracker. It involves giving the model a pile of source material and a goal, letting it handle judgment calls via rough guidelines.
- **Role**: evidence

### The Economics of Scale
- **Anchor Timestamps**: ['00:06:18']
- **Claim**: Small asks are economically wasteful for expensive models. Users must prepare data packs that take hours to assemble, aiming for tasks that save weeks of work, justifying the cost and effort of 'care and feeding' the model.
- **Role**: evidence

### The Model Manager Role
- **Anchor Timestamps**: ['00:13:09']
- **Claim**: This shift creates a new role: the model manager. It requires directing, aiming, and judging the model's output. Jobs are not killed by automation but by the need for humans to provide the necessary context, data, and oversight for high-quality results.
- **Role**: synthesis

## Evidence and caveats

The speaker notes that while the model quarantines garbage data and builds review queues, it still has misses: visual taste is lacking, it can miss handwritten info, and it is expensive ($50/1M output tokens). It is not a daily driver for small tasks like email summaries. The model needs 'care and feeding'—clear scope, data packs, and human review. It does not kill jobs requiring judgment, only strict execution roles. The speaker admits the model is not perfect but is powerful enough to tackle 'gnarly' problems like merging 2 million customer records or fact-checking 500-page board packets.
