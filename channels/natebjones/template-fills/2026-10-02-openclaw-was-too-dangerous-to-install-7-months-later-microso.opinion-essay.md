## Thesis

Microsoft's Autopilot, built on OpenClaw-derived technology, will reach far more workers than any other AI this year, and the value it delivers depends on data access and user skill, not model intelligence.

## Argument

The mechanism is distribution. Microsoft's 450 million paid Microsoft 365 seats dwarf OpenAI's 9 million business users, and Autopilot is embedded in the tools people already use—Excel, Outlook, Teams. This isn't about being smarter; it's about being everywhere. The real value comes from the data it can access and how well you use it. The future is K-shaped: people with the same tools get wildly different results. To land on the upward slope, you need five practices.

First, define what 'good' looks like. Give Autopilot a specific task tied to a real outcome, like identifying outstanding customer obligations before a renewal. Show it an example of a useful briefing. Second, put the right information in front of the model and verify it used it. Provide the account plan, the commitments, the service history. Tell it which source takes priority. Ask for an evidence tree—links to sources—and check if the response actually reflects the latest data. Third, make good tasks repeatable. Set up scheduled prompts or agent triggers so the work happens without you remembering to ask. Fourth, match reasoning to complexity. Separate routine preparation from consistent interpretation. Use stronger models for the hard parts, and give them the context they need—what you've tried, why the obvious answer failed. Fifth, obsess over improving the next run. When a briefing misses a commitment, find out why: missing source, unclear instructions, or the model didn't understand. Fix the cause, save the fix, share it with a colleague.
