## Thesis

Microsoft is bringing OpenClaw-derived agent technology to the enterprise as Autopilot, and the value it creates depends on data access and user skill, not model intelligence.

## Argument

The mechanism is distribution. Microsoft's 450 million paid Microsoft 365 seats dwarf OpenAI's 9 million business users, and Autopilot is embedded in the tools people already use—Excel, Outlook, Teams. This means the AI you have access to is about to start doing a different kind of work: completing tasks while you do something else, not just answering questions. The value comes from the data it can use and how well you know how to use AI. The future takes a K-shape: people with the same tools get very different results. To land on the upward slope, you need five practices. First, define what 'good' looks like—give Autopilot a specific task and tell it what a useful outcome is. Second, put the correct information in front of the model and check if it actually used it; give it the account plan, commitments, service data, and tell it which sources take priority. Third, make a good task repeatable—set a trigger, define what it's responsible for between runs, and test the next iteration. Fourth, match reasoning to complexity—separate routine preparation from consistent interpretation, and consciously use stronger models for the hard parts. Fifth, obsessively improve the next launch—fix the cause of failures, keep what works, and share it with colleagues. Microsoft's advantage is data access and trust, not model smarts. ## Counterpoints

- A sufficiently powerful model can find a more efficient way to prepare updates, potentially eliminating the need for weekly reports or meetings that exist only to coordinate human activity.
- Microsoft doesn't have its own frontier model, so it may lose to labs like Anthropic that can redesign corporate processes from scratch.
- Automatic routing can waste tokens if it can't distinguish between trivial and complex tasks, making a smart model more cost-effective in the long run.
