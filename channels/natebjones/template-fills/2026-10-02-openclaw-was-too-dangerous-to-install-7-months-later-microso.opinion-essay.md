## Thesis

Microsoft is bringing OpenClaw-derived agent technology to the enterprise as Autopilot, and the value it delivers will depend not on model intelligence but on data access and user skill.

## Argument

The mechanism is distribution. Microsoft's 450 million paid Microsoft 365 seats dwarf OpenAI's 9 million business users, and Autopilot is embedded in the tools people already use—Excel, Outlook, Teams. This means the AI you have access to is about to start doing a different kind of work: completing tasks while you do something else. The value comes from the data it can use and how well you know how to use AI. The future takes a K-shape: people with the same tools get very different results. To land on the upward slope, you need five practices. First, define what 'good' looks like—show the model an example and explain what's useful. Second, put the correct information in front of the model and check if it actually used it; give it the account plan, the commitments, and tell it which source takes priority. Third, make a good task repeatable—set a trigger, define what the agent is responsible for between runs, and test the next launch. Fourth, match reasoning to complexity—separate routine preparation from consistent interpretation, and give hard problems the context and opportunities they need. Fifth, obsessively improve the next use—find out why a commitment was omitted, fix the cause, and share what works. Microsoft's advantage is that it can monetize trust and distribution, but the strongest argument against assuming Microsoft wins is that better models can redesign the processes you planned to automate, as Anthropic's guided agents suggest.

## Counterpoints

- A sufficiently powerful model can find a more efficient way to prepare updates, potentially eliminating the need for weekly reports and meetings that exist only to coordinate human activity.
- Microsoft doesn't have its own frontier model, so it may lose the intelligence race to labs like Anthropic, which could redesign corporate workflows more efficiently.
- Automatic routing can be counterproductive: you might spend more tokens figuring out what task you're doing than just sending it to a smart model, and routers can't distinguish between 'What is this?' for a syntax error vs. a complex coding problem.
