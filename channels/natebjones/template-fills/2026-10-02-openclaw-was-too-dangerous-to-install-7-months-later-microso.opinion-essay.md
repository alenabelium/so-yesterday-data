## Thesis

Microsoft's Autopilot, built on OpenClaw, will reach far more workers than any other AI this year, and its value depends on data access and user skill, not model intelligence.

## Argument

The mechanism is distribution. Microsoft's 450 million paid Microsoft 365 seats dwarf OpenAI's 9 million business users, and Autopilot is embedded in the apps where work already happens. The agent isn't smarter—it's just everywhere. Value comes from the data it can use and how well you use it. The K-shaped future: same tools, wildly different results. Five practices determine which slope you're on. First, define what 'good' looks like. Give Autopilot a real task and tell it what a useful outcome is. Second, put the right context in front of the model and verify it used it. Most people don't. Third, make good tasks repeatable. Set triggers, schedules, and limits. Fourth, match reasoning to complexity. Routers can't tell a trivial 'what is this?' from a deep debugging question. Fifth, obsess over improving the next run. Fix the cause, save the fix, share it. Microsoft's advantage is data access, not intelligence. But the strongest counterargument is that better models will redesign workflows entirely, making Microsoft's process-based advantage obsolete.

## Counterpoints

- Microsoft's model isn't the smartest, so why bother? Because value comes from data access and user skill, not raw intelligence.
- Autopilot is still in preview and not rolled out to half a billion people overnight, so the impact may be gradual.
- A sufficiently powerful model could redesign workflows, eliminating the need for Microsoft's process-heavy approach.
- Router systems may cost more tokens to figure out than just using a smart model, especially for complex new problems.
