## TL;DR

AI agents fail at real work not because of model limits, but because software lacks semantic work primitives that define the meaning and authority of actions. Computer use gives agents access, but true autonomy requires exposing intent, permissions, and consequences. The future belongs to agent-native software where the meaningful action itself is the primitive.

## The argument

### Define the Work Primitive
- **Anchor Timestamps**: ['00:00:00']
- **Claim**: The work primitive is the semantically meaningful unit of work—like a refund, reschedule, or compliance exception—that agents need to understand. Computer use only provides access, but the real strategy is controlling the meaning behind actions.
- **Role**: definition

### Three Layers: Access, Meaning, Authority
- **Anchor Timestamps**: ['00:02:09']
- **Claim**: Computer use gives agents access. Semantic work primitives give meaning. Authority is the deepest layer. Companies that control these primitives gain platform power, not those who merely let agents click buttons.
- **Role**: definition

### Computer Use Is a Bridge, Not a Moat
- **Anchor Timestamps**: ['00:03:59']
- **Claim**: Computer use is a universal adapter for the messy middle period, but it's shallow. It doesn't reveal domain meaning or consequences. Guessing is not a strategy for high-consequence work; agents need richer semantic interfaces.
- **Role**: evidence

### Coding Agents Lead Because of Rich Semantics
- **Anchor Timestamps**: ['00:10:21']
- **Claim**: Coding agents work first because codebases have modules, tests, and type systems that give agents semantic feedback. Most knowledge work lacks this density, which is why coding is the wedge—not because all work becomes coding, but because it's legible enough for autonomy.
- **Role**: evidence

### The Platform Fight Over Meaning
- **Anchor Timestamps**: ['00:19:44']
- **Claim**: The coming fight is over which layer owns the meaning of work. Model companies, browser companies, SaaS companies, and identity providers all have interests. Software must expose semantic access carefully or risk becoming infrastructure for someone else's agentic interface.
- **Role**: synthesis

## Evidence and caveats

**Examples:**
- Calendar invites: moving a meeting may notify five people, break commitments, or conflict with priorities—semantic context humans carry but agents miss.
- Checkout: a 'buy' button represents money, consent, tax, fraud risk, fulfillment, and disputes.
- Deleting a file: one is harmless cleanup, another is the only copy of a signed agreement.
- Coding agents: tests are semantic meaning artifacts that tell the agent if it's wrong.

**Caveats:**
- Computer use is necessary for the messy middle, but it's a shallow interface.
- Most knowledge work lacks semantic density—strategy docs don't have tests.
- The bridge between computer-side and meaning-side approaches has holes.
- Exposing too much semantic access risks becoming back-end infrastructure; too little makes agents clumsy.
