# Google cracks recursive self improvement

**[00:00:00]** No waifu today, but Google DeepMind recently released a very interesting paper on what they call continuous recursive self-improvement. The main idea is to give AI a permanent memory of its own mistakes, allowing it to continuously improve, instead of starting from scratch every time it performs a new task. Now, to understand what this article is about, we first need to figure out what exactly this "harness" is.

**[00:00:53]** You see, when you interact with a large language model, especially an advanced one, it usually doesn't do all the work on its own. Instead, there is a certain " harness" that controls or directs its actions. There are currently several well-known solutions for advanced models. For example , Claude Code is a harness for Claude, Codex is for GPT, Anthropic Gravity is for Gemini, there is also a DeepSeek harness for DeepSeek, and these are just a few examples. You can think of this binding as a software wrapper around the model. It provides a workspace, tools , memory, and rules for AI. It allows AI to search the web, read or write files, or call other tools. The binding also manages memory and context so that the model doesn't lose track of the session, especially if it's very long or involves many steps . It also sets permissions and asks for human approval before allowing AI to perform risky actions.

**[00:01:48]** So you can think of an AI model as an engine. It is capable of generating power and speed, but cannot steer, brake, or go anywhere on its own. There has been a lot of research recently on optimizing such systems , as you can see from all these links. Actually, this is what the recursive self-improvement in this article points to. They essentially invented a way to make the AI ​​ model use feedback from its own sessions to rewrite and optimize its own binding. And this, in turn, allows AI to work better within the envelope. So it's like a positive feedback loop . It sounds great in theory. AI performance will improve as the shell becomes more optimized. But what happens if we want to change the basic model?

**[00:02:40]** Let's say we spent a few weeks using Claude Opus 5.5 to optimize and develop a shell around it. But now we want to transfer this shell to the Gemini model. Ideally, we would like all of this optimization to be carried over to the new model, as it would save us the time of having to build a new shell from scratch. And of course, the new AI model has to be smart enough to adapt to the shell, right? Well, unfortunately, researchers have proven the opposite. They took a shell that had been recursively developed and optimized by Claude Opus' model and tested it on tasks in a simulated desktop environment . That is, things like using the operating system, opening browsers, and working with various files. But then they used this shell with the Gemini model, and it actually performed worse on these tasks. Sometimes even worse than if they had just used a completely blank shell from scratch. So , they showed that a high-performance shell actually hurts performance if you change the model. So it seems that everything learned during the self-development of the Opus model was not properly transferred to the new Gemini model with the same shell, which is not ideal. So here is the main innovation of this article. They call it SIM, which stands for " self-improvement memory." Instead of simply transmitting the final code of the developed shell, SIM transmits a structured permanent record of the entire improvement process. This effectively gives the AI ​​ a notebook of its own evolutionary history. And here's how it works. Each SIM record contains several structured fields . First, it records the root cause of the problem the system encountered, such as the bug itself. He then records the rationale, the predicted outcome of the correction, and finally the actual outcome. Additionally, it also logs the specific model and domain where the errors occurred. Essentially, it records what was tried and what actually worked or failed. You might think this is too much information. Wouldn't it be enough to simply tell the AI ​​ what the mistake was? Why does he need all this history plus a comparison of expected and actual results or the name of the model he used? This seems excessive. Well, researchers thought the same thing . So, to test whether all this data was really necessary, they conducted an ablation experiment. Ablation is when you simply remove a certain factor to see if it affects the results. They tested a condition called "problem-only memory," which removed the history and results, giving the AI ​​ only a list of errors. And the results were quite clear. The full SIM recording consistently outperformed the problem-only memory in all aspects. In fact, in some cases, having memory only about the problem performed worse than having no memory at all, which is quite surprising. But you can think of it something like this. Knowing what the problem is doesn't give AI historical evidence of what has already been tried and how it didn't work. Here is a theoretical example where AI has to learn to fix a leaking pipe. If you simply tell the AI ​​ that the pipe is leaking, it may try the same sealant that didn't help. He will simply get stuck in a cycle of repeating past mistakes. But if the SIM record captures everything, for example: we predicted that this sealant would work, but the result was negative—now the AI ​​ has actionable information. He has the complete picture to decide what to do next.
