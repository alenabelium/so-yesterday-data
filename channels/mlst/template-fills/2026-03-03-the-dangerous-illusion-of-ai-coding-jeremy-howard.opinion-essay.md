## Thesis

AI coding tools like Claude Code create an illusion of control and productivity, but they degrade human skills and organizational knowledge, and they are fundamentally poor at software engineering.

## Argument

The core problem is that AI coding tools are evaluated on generation, not engineering. They can produce code that looks plausible, but they lack the deep understanding required for real software engineering, which involves intuition, interaction, and building mental models. This is why they fail at novel problems: they interpolate from training data, not extrapolate. The result is a 'slot machine' dynamic—users tinker with prompts and feel in control, but the output is stochastic and often incomprehensible. This leads to a fatal loss of control as AI-generated code accumulates, and no one understands the system. The solution is not to abandon AI but to place it in rich, interactive environments like notebooks, where humans and AI can collaborate and maintain understanding. This is the philosophy behind tools like nbdev and Solve, which contrast sharply with the linear, terminal-based interfaces of tools like Claude Code.

## Counterpoints

- Some argue that LLMs are creative and can solve novel problems, but this is combinatorial creativity within the training distribution, not true extrapolation.
- Proponents claim AI coding makes developers 50x more productive, but this is often an illusion; studies show minimal real-world productivity gains.
- There is an optimistic view that functionalism means we don't need to understand the code if it works, but this ignores the risk of accumulating technical debt and losing control.
- Some say AI coding is just a matter of AI literacy and that effective users can create feedback loops, but the tools themselves are not designed to foster understanding.
- The argument that AI will lead to mass unemployment ignores that software engineering is more than coding and that human skills remain essential.
