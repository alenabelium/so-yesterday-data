## Thesis

AI coding tools like Claude Code create a dangerous illusion of control that degrades human skills and organizational knowledge, and they are fundamentally poor at software engineering, which requires deep intuition and interaction.

## Argument

The core problem is that LLMs are not creative in the way humans are; they interpolate within their training data, which is why they fail when asked to design something genuinely new. This is why the 'vibe coding' hype is misplaced: it conflates coding (a style transfer task) with software engineering, which is about understanding and assembling components. The evidence is clear: even for an expert like Jeremy, AI-generated code is often a black box, and the '50x productivity' claims don't hold up in real organizations. The real danger is that over-reliance on these tools leads to a 'cognitive debt' where people stop developing their own understanding, and organizations lose the embodied, living knowledge that is essential for innovation. The solution is not to abandon AI but to build rich, interactive environments like notebooks where humans and AI can collaborate, maintaining a feedback loop that fosters understanding rather than replacing it.

## Counterpoints

- Some argue that LLMs are creative, but they only perform combinatorial creativity within their training distribution, not true extrapolation.
- Dario Amodei and others claim AI will lead to mass unemployment because engineers are more productive, but this ignores that most software engineering is not about writing code.
- The optimistic view of functionalism suggests that if AI-generated code works, we don't need to understand it, but this leads to a fatal loss of control when something breaks.
- Some say that using AI tools is a matter of AI literacy, but if a tool doesn't naturally help people become more knowledgeable, it's a problem with the tool itself.
- The argument that AI will be so powerful that we must centralize it is dangerous; power should be distributed, not concentrated.
