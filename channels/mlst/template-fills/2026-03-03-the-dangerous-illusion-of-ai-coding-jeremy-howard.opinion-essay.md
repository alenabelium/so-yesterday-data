## Thesis

AI coding tools are a dangerous illusion that degrade human skills and organizational knowledge, and true software engineering will always require human intuition and interaction.

## Argument

The core problem is that LLMs are fundamentally imitative, not understanding. They can generate code by interpolating between training data, but they lack the deep intuition and mental models that come from direct interaction with a system. This is why they are terrible at software engineering, which is about designing, composing, and understanding components, not just writing code. The 'vibe coding' trend is a slot machine: it gives an illusion of control, but the code produced is often a black box that no one understands, leading to a fatal loss of control and accumulated technical debt. This is not just a personal issue; it's an organizational one. When you delegate cognitive tasks to AI, you blur knowledge inside the organization, and you lose the ability to create and develop knowledge. The only way to build truly great software is through rich, interactive environments like notebooks, where humans and AI can collaborate, iterate, and build a shared understanding. This is the opposite of the linear, terminal-based interfaces that tools like Claude Code provide, which are inhumane and counterproductive.

## Counterpoints

- Some argue that AI can be creative, but this is combinatorial creativity, not the ability to extrapolate beyond training data.
- Dario Amodei and others claim AI will lead to mass unemployment, but this ignores that most software engineering is not coding.
- The optimistic view of functionalism suggests that if AI code works, we don't need to understand it, but this leads to a fatal loss of control.
- Some say AI coding is a matter of AI literacy, but if a tool doesn't naturally help people become more knowledgeable, it's a problem with the tool, not the user.
