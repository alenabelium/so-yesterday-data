## Thesis

AI coding tools are a dangerous illusion that degrade human skills and organizational knowledge, and true software engineering requires deep understanding that LLMs fundamentally lack.

## Argument

The core problem is that AI coding tools like Claude Code are built on a false premise: that generating code is the same as engineering software. As Jeremy Howard argues, coding is a style-transfer task—interpolating between existing training data—while software engineering is about deep intuition, understanding constraints, and building mental models through interaction. This is why LLMs are terrible at engineering: they fail when asked to create something genuinely new, and they produce code that no one understands, creating a fatal loss of control. The slot-machine metaphor captures the illusion: you tweak prompts and pull the lever, but the outcome is stochastic and often a loss disguised as a win. The real danger is organizational: when you delegate cognitive tasks to AI, you blur knowledge inside organizations. People stop developing their own skills, and the accumulated technical debt becomes a ticking time bomb. The solution is not to abandon AI but to put it in rich, interactive environments like notebooks, where humans and AI can collaborate in real time, maintaining understanding and control. This is the antithesis of the linear, terminal-based Claude Code experience, which is 'inhumane' and strips away the joy and growth that come from direct engagement with your work.

## Counterpoints

- Some argue that LLMs are creative, but this is combinatorial creativity within training data, not true extrapolation beyond it.
- Dario Amodei's claim that AI will lead to mass unemployment is based on a misunderstanding of software engineering; most work is not coding.
- The optimistic view of functionalism—that if the code works, it doesn't matter if no one understands it—ignores the fatal loss of control and the inability to maintain or extend such systems.
- Some say AI tools can be used effectively with the right skills (AI literacy), but if the tool doesn't naturally help people become more knowledgeable, it's a problem with the tool, not the user.
- The argument that AI coding is like a slot machine is countered by the fact that some tasks are well-suited for AI, but these are limited and require human oversight.
