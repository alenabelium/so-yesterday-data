## Thesis

AI coding tools like Claude Code create an illusion of control and productivity, but they degrade human skills and organizational knowledge, and they are fundamentally poor at software engineering, which requires deep intuition and.

## Argument

The core problem is that AI coding tools are evaluated and used as slot machines: you tinker with prompts and pull the lever, getting code that nobody understands. This is not software engineering. Software engineering is about building mental models through interaction, as Feynman and other great scientists demonstrate. LLMs only imitate understanding; they interpolate within their training data, which is why they fail when asked to go beyond it. The famous 'clean room' C compiler from Anthropic is just a style transfer from LLVM code, not genuine creation. The real bottleneck is knowledge: when you delegate cognitive tasks to AI, you blur knowledge inside organizations. People in the middle of their careers, who are not novices or experts, risk becoming obsolete because they don't develop the deep understanding needed to move from point A to point B. The solution is not to abandon AI but to create rich, interactive environments like notebooks where humans and AI can collaborate, with feedback loops that foster understanding. This is the opposite of the linear terminal interface of Claude Code, which is a regression to 40-year-old paradigms. We need to focus on designing tools that naturally make people more knowledgeable and happy, not just tools that complete tasks autonomously.

## Counterpoints

- Some argue that LLMs are creative because they can produce novel combinations, but this is combinatorial creativity within the training distribution, not true extrapolation.
- Dario Amodei and Elon Musk claim AI will automate all coding, but they misunderstand the difference between coding and software engineering; most engineering work is not writing code.
- Anthropic's study on productivity gains from AI coding is contradicted by research showing productivity actually fell for 'vibe-coding' users.
- The optimistic view of functionalism suggests that if AI-generated code passes tests, it doesn't matter if we understand it, but this ignores the fatal loss of control and the risk of unmaintainable code.
- Some argue that AI coding tools can be used effectively with proper AI literacy, but the tool itself should be designed to naturally foster understanding, not require special skills.
