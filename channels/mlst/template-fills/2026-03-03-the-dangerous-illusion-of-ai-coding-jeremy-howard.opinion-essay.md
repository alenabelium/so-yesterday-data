## Thesis

AI coding tools create an illusion of control and productivity, but they degrade human skills and organizational knowledge, and the real bottleneck is software engineering, not code generation.

## Argument

The core problem is that LLMs excel at style transfer, not at genuine software engineering. They interpolate between training data, producing code that looks plausible but lacks the deep understanding required for novel, complex systems. This is why the productivity gains are often illusory: the code is generated, but the engineering—the design, the integration, the debugging—still requires human expertise. The real risk is not that AI will replace engineers, but that over-reliance on it will erode the very skills needed to build and maintain software. This is a 'desired difficulty' problem: without the effort of understanding, we don't learn, and we accumulate 'understanding debt.' The solution is not to abandon AI, but to embed it in rich, interactive environments like notebooks, where humans and AI can collaborate, and where the human maintains a deep mental model of the system. This is the antithesis of the 'slot machine' experience of tools like Claude Code, which encourage a passive, stochastic approach to coding.

## Counterpoints

- Some argue that AI-generated code is fine as long as it works, but this ignores the problem of unmaintainable code that no one understands, as seen with the ipython kernel fix.
- Dario Amodei and others claim that AI will make software engineers massively more productive, but this extrapolates from elite engineers and ignores the middle majority who lack the experience to guide AI effectively.
- The optimistic view is that we can treat software as functional components, but this fails when the components are too large and poorly understood, leading to systemic failures.
- Some believe that AI can be creative, but it only performs combinatorial creativity within its training distribution, and it cannot extrapolate beyond it.
- The argument that AI will lead to mass unemployment ignores the fact that software engineering is not just coding, but involves design, integration, and understanding, which AI cannot do.
