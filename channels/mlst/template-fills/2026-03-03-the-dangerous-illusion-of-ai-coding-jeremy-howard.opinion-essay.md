## Thesis

AI coding tools like Claude Code create a dangerous illusion of control that degrades human skills and organizational knowledge, and they fail at true software engineering, which requires deep intuition and interactive understanding.

## Argument

The core problem is that AI coding tools are fundamentally different from software engineering. Coding is a style-transfer task—interpolating between training data—while software engineering requires deep intuition, mental models, and interactive understanding of the system. As Jeremy Howard puts it, 'they really bad at engineering software software. And I I think that's probably it. , will always be true.' This is because engineering involves manipulating objects in real time, studying them, and moving them, which is something humans do far better than machines. The illusion of control comes from the slot-machine-like nature of these tools: you tinker with prompts, configure MCPs, and pull the lever, but you get code that nobody understands. This leads to a fatal loss of control, as seen in the ipython kernel incident where AI-generated code fixed a problem but left a piece of code that no one understands, making it impossible to bet on it for a company product. The real danger is that over-reliance on AI degrades human skills and organizational knowledge. As Howard notes, 'if you don't use actively develop your skills design, engineering and coding, you don't you are developing. You you can even degrade.' This is especially true for mid-level developers who risk becoming obsolete. The solution is to create rich, interactive environments like notebooks where humans and AI can collaborate, fostering understanding and growth, rather than the linear terminal interfaces that dominate current AI coding tools.

## Counterpoints

- Some argue that AI coding tools make individuals 50 times more productive, but this doesn't transfer to organizations because of knowledge bottlenecks.
- Proponents claim that AI can handle complex tasks like fixing the ipython kernel, but this results in code that no one understands, creating a fatal loss of control.
- Optimists believe that functionalism means we don't need to understand the code if it works, but this ignores the need for high-quality software engineering to build larger systems.
- Critics say that AI is creative, but it only performs combinatorial creativity within training data, not true extrapolation beyond the distribution.
- Some argue that AI can automate routine tasks and free up experts, but this only works if the automation is truly effective and doesn't degrade the expert's skills.
