## Thesis

AI coding tools like Claude Code create an illusion of control and degrade human skills, while true software engineering requires deep intuition and interactive environments that LLMs cannot replace.

## Argument

The mechanism is the slot machine effect: users tinker with prompts, MCPs, and skills, but ultimately pull a lever and get code nobody understands. This stochastic process feels productive but rarely yields quality. Jeremy Howard's own experience with the IPython kernel fix shows the limits: even when AI solved a complex bug, he felt stressed and lacked control, because the code was opaque. The real bottleneck is knowledge accumulation. When AI writes 90% of code, the human loses the deep understanding needed to debug, extend, or share that code. This is why productivity gains are tiny in real organizations, despite individual hype. The solution is not to abandon AI, but to embed it in rich, interactive environments like notebooks, where humans and AI can collaborate with feedback loops, preserving and growing human competence.

## Counterpoints

- Some argue LLMs are creative, but they only interpolate within training data, not extrapolate beyond it.
- Dario Amodei claims AI makes engineers super productive, but Anthropic's own study showed no learning gains.
- Functionalists say if AI code works, it doesn't matter if we understand it, but this leads to fatal loss of control.
- AI coding is like a slot machine: illusion of control, intermittent rewards, and addictive behavior.
- Some say AI can replace software engineers, but coding is not engineering; engineering requires decades of intuition.
