## Thesis

AI coding tools like Claude Code create an illusion of control and productivity, but they degrade human skills and organizational knowledge, and they are fundamentally poor at software engineering.

## Argument

The core problem is that AI coding tools are designed for style transfer, not genuine engineering. They interpolate between existing code in training data, which works for routine tasks but fails when you need to build something genuinely new. This is why they are terrible at software engineering, which requires deep intuition and interaction with the system. The evidence is everywhere: the ipython kernel fix was a two-week ordeal of babysitting models, and the resulting code is a black box that no one understands. The real bottleneck is not code generation but the human knowledge required to specify, design, and integrate components. When you delegate cognitive tasks to LLMs, you blur knowledge inside organizations, creating a paradoxical effect where you lose the very expertise you need to use the tools effectively. The solution is not to abandon AI but to create rich, interactive environments like notebooks where humans and AI can collaborate, with feedback loops that foster understanding and growth.

## Counterpoints

- Some argue that LLMs are creative and can solve novel problems, but this is combinatorial creativity within the training distribution, not true extrapolation.
- Dario Amodei and Elon Musk claim AI will automate all coding, but they haven't been engineers recently and misunderstand the discipline.
- The optimistic view is that functionalism means we don't need to understand the code if it works, but this leads to a fatal loss of control and technical debt.
- Some say AI coding is a matter of AI literacy, but if the tool doesn't naturally help people become more knowledgeable, it's a problem with the tool itself.
- The existential risk argument is a distraction; the real danger is centralizing power and letting people become weaker.
