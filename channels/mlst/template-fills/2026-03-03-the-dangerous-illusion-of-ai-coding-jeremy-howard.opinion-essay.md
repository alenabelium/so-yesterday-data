## Thesis

AI coding tools are dangerous because they create an illusion of control while degrading human skills and organizational knowledge, and they are fundamentally poor at software engineering.

## Argument

The core problem is that AI coding tools like Claude Code are not designed for software engineering, which requires deep intuition and interaction. They are good at style transfer—interpolating between existing code—but fail when asked to create something truly novel. This is because they operate within the distribution of their training data and cannot extrapolate beyond it. When they do produce code, it often comes from a 'slot machine' dynamic: you tinker with prompts and pull the lever, getting a piece of code that nobody fully understands. This leads to a loss of control and a buildup of technical debt, as seen with the ipython kernel incident. The real danger is that this degrades human competence. People in the middle of their careers, who are not beginners or experts, risk becoming obsolete if they rely on AI without building their own understanding. Organizations that push this approach are cutting off their own legs, losing the ability to develop knowledge and adapt. The solution is not to abandon AI but to create rich, interactive environments like notebooks that foster understanding and collaboration between humans and AI, allowing both to grow.

## Counterpoints

- Some argue that AI coding tools make developers more productive, as Dario Amodei claimed, but this is based on anecdotal evidence from expert engineers, not the average developer.
- There is a view that AI can be creative, but this is only combinatorial creativity within the training distribution; it cannot extrapolate beyond it.
- The optimistic functionalist view says that if the code works, it doesn't matter if we understand it, but this ignores the risk of losing control and the inability to fix unforeseen issues.
- Some say that AI can handle complex tasks like fixing the ipython kernel, but this required significant human effort and left the code in a state that no one fully understands.
- The analogy to calculators in schools suggests that we should let beginners use AI, but this may prevent them from developing the necessary skills and understanding.
