## 2. DeepMind LEAN-verifies libsignal at machine-code level, a first for a widely deployed protocol

DeepMind's AlphaProof Code framework formally verified key security properties of libsignal, the cryptographic protocol behind Signal, at the machine code level—a first for a widely deployed, unmodified implementation. The multi-agent system generated 6.5 million lines of Lean proofs in four weeks, a task that historically took years, signaling a major leap in practical AI-driven formal verification.

## 5. MCP tool setups consume up to 60,000 tokens, exposing inefficiency in agent workflows

A practical analysis reveals that MCP tool setups can use up to 60,000 tokens, while CLI uses only 1,500 tokens, highlighting a significant efficiency gap in agent tool integration. This insight is crucial for developers and enterprises optimizing AI agent performance and cost, especially as agentic workflows become mainstream.

<!--detail
The quiet inefficiency hiding inside agentic workflows is finally getting a number attached to it: a Model Context Protocol (MCP) tool setup can burn up to 60,000 tokens before a single useful action occurs, while a comparable CLI invocation costs roughly 1,500 tokens. That is a 40x gap, and it is not a rounding error—it is the difference between an agent that feels responsive and one that feels like a slow, expensive intern reading the entire manual before answering a question.

The source video frames this as a practical warning rather than a verdict against MCP itself. The tension here is between architectural purity and operational reality. MCP offers a standardized, discoverable way to expose tools to agents, which is why enterprises are adopting it as the connective tissue for multi-agent systems. But that standardization comes with a tax: the agent must ingest tool schemas, descriptions, and parameter definitions before it can even decide which tool to call. The video's implicit hedge is that this is not an argument to abandon MCP, but to treat tool discovery as a first-class design problem rather than an afterthought. The 60,000-token figure likely reflects a poorly curated tool namespace—dozens of verbose schemas loaded wholesale—whereas the CLI comparison suggests a leaner, more targeted interface.

For practitioners, the actionable takeaway is to audit your tool surface area the way you would audit your codebase. Are you exposing 50 tools when your agents realistically use five? Are schemas written with verbose descriptions that repeat what the tool name already says? The efficiency gap is not inherent to MCP; it is a symptom of lazy tool design. Teams should implement tool-search or lazy-loading strategies, prioritize concise schema descriptions, and measure token consumption per agent task as a core performance metric. As agentic workflows scale from pilots to production, this 40x difference will compound into real cost and latency penalties—and the teams that design for token efficiency now will have a structural advantage.
