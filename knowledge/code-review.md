Code review is a systematic examination of source code by one or more developers, typically before merging into a shared codebase. It serves multiple purposes: catching bugs early, ensuring code quality and consistency, sharing knowledge across the team, and maintaining a shared sense of ownership. Effective code review is not just about finding defects—it's a collaborative process that improves both the code and the developers who write it.

Modern code review has evolved from formal inspections to lightweight, tool-assisted practices like pull requests and Gerrit. With the rise of AI, automated tools now assist reviewers by flagging potential issues, suggesting improvements, and even generating review comments. However, human judgment remains essential for assessing design trade-offs, architectural fit, and long-term maintainability.

## Key Aspects
- **Bug Detection**: Reviews catch logic errors, edge cases, and security vulnerabilities that automated tests might miss.
- **Knowledge Sharing**: Reviewers learn from each other's code, spreading expertise and reducing bus factor.
- **Quality Standards**: Enforces coding conventions, best practices, and architectural guidelines consistently.
- **AI Assistance**: AI-powered review tools can automate routine checks, but human oversight is still needed for nuanced decisions.
